# Notifications

The notify service lets applications send Web Push notifications to Rotur users. Apps register a user's browser push subscription under a source name, and other accounts that the user allows can then push to it.

> **Base URL:** `https://api.rotur.dev`
>
> **Auth:** Every endpoint except [GET `/notify/vapid`](vapid-keys.md) requires your token in the `Authorization: Bearer <token>` header. A session cookie and the legacy `auth` query parameter are also accepted.

Authenticated requests also need a verified email address and accepted Terms of Service; otherwise you get a `403`. Sub-tokens need these permissions (your main token has all of them):

| Permission | Needed for |
| --- | --- |
| `notifications:view` | Checking registration, listing endpoints, allowed and blocked senders, the log, notifiable users |
| `notifications:send` | Sending notifications |
| `account:settings` | Registering endpoints, deleting devices, changing allowed and blocked senders |

A token without the permission gets `403` with `{"error": "Token lacks permission: <permission>"}`.

## Concepts

### Sources

A source is the name of the app or site that registers an endpoint, for example `originChats`. Every endpoint belongs to one source, and users allow senders per source.

When a notification is sent for a source that has no devices registered on the recipient's account, it goes to the devices registered under the `rotur.dev` source instead. Enabling push on rotur.dev therefore covers Rotur's own notifications, such as group invites, and any source without its own device.

### Device IDs

Device IDs are generated by the server as an HMAC of your username, the source and a `fingerprint` you provide. The fingerprint should be a stable string derived from the device (for example a hash of user agent, screen and timezone). The same fingerprint and source always give the same device ID, so registering again updates the existing endpoint instead of adding a duplicate.

### Who can push to you

Push delivery needs all of the following:

* You allowed the sender for that source ([allowed senders](allowed-senders.md)). Nobody is allowed by default.
* You have not blocked the sender from notifications ([blocked senders](allowed-senders.md#blocked-senders)).
* You have not turned push off. `push_enabled` defaults to `true` and is read and changed with `GET` and `PUT /v2/me/notifications/preferences`.
* You have at least one device registered for the source, or for `rotur.dev`.

If you have blocked the sender as a user, the send request is rejected with `403`. In every other case the notification is still added to your [notification log](notification-log.md) and your [notification feed](../../claw/api-endpoints/notifications.md), even when no push is delivered.

### Storage

Registered endpoints are stored in your originFS at:

```
origin/(c) users/<username>/application data/notify@rotur/endpoints.json
```

Allowed senders are stored on your account under `sys.notify_allowed`, and blocked senders under `sys.notify_blocked`.

## Endpoints

| Endpoint | Auth | Description |
| --- | --- | --- |
| [GET `/notify/vapid`](vapid-keys.md) | No | Get the server's VAPID public key |
| [POST `/notify/register`](register-endpoint.md) | Yes | Register a push endpoint |
| [GET `/notify/check`](check-registration.md) | Yes | Check if a device is registered |
| [GET `/notify/endpoints`](list-endpoints.md) | Yes | List your registered endpoints |
| [DELETE `/notify/device/:device_id`](delete-device.md) | Yes | Remove a registered device |
| [GET `/notify/allowed`](allowed-senders.md) | Yes | List allowed senders |
| [POST `/notify/allowed/:username`](allowed-senders.md) | Yes | Allow a sender |
| [DELETE `/notify/allowed/:username`](allowed-senders.md) | Yes | Remove an allowed sender |
| [GET `/notify/blocked`](allowed-senders.md#blocked-senders) | Yes | List blocked senders |
| [PUT `/notify/blocked/:username`](allowed-senders.md#blocked-senders) | Yes | Block a sender |
| [DELETE `/notify/blocked/:username`](allowed-senders.md#blocked-senders) | Yes | Unblock a sender |
| [GET `/notify/log`](notification-log.md) | Yes | View notifications you received |
| [POST `/notify/:username`](send-notification.md) | Yes | Send a notification to one user |
| [POST `/notify/`](send-notification.md) | Yes | Send a notification to many users |
| [GET `/notify/:source/users`](notifiable-users.md) | Yes | List users who allow you for a source |

The same endpoints exist under `/v2`. These paths differ:

| v1 | v2 |
| --- | --- |
| `DELETE /notify/device/:device_id` | `DELETE /v2/notify/devices/:device_id` |
| `POST /notify/allowed/:username` | `PUT` or `POST /v2/notify/allowed/:username` |
| `POST /notify/:username` | `POST /v2/notify/users/:username` |
| `POST /notify/` | `POST /v2/notify`, `POST /v2/notify/` or `POST /v2/notify/users` |
| `GET /notify/:source/users` | `GET /v2/notify/sources/:source/users` |
